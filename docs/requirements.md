# منظومة جامعة العاصمة لإدارة الأداء الاستراتيجي ومتابعة خطة Tier 1

**وثيقة المتطلبات — الإصدار 0.2 (مسودة للمراجعة)**
**التاريخ:** 2026-11-10

المرجعان: ملف «مؤشرات الكليات» (12 صفحة) وملف «نموذج الجامعات المصرية الرائدة Tier 1» (26 صفحة، 12 معيارًا).
البيانات المستخرجة منهما وسجل التعارضات في [reference/قاموس_المؤشرات_Tier1_مسودة.xlsx](../reference/قاموس_المؤشرات_Tier1_مسودة.xlsx).

## 1. الهدف والنطاق

تحويل خطة Tier 1 إلى منظومة تشغيل ومتابعة تربط بين المؤشرات والمستهدفات وبيانات الجهات والمبادرات والميزانيات والأدلة والقرارات.

**المستفيدون:** رئاسة الجامعة ونواب الرئيس، والجهة المركزية لمتابعة الخطة، ومركز ضمان الجودة والاعتماد، والكليات والمعاهد والأقسام العلمية، والمراكز والإدارات المالكة للبيانات، والجهات المنفذة للمبادرات.

**الإطار الزمني:** خط أساس 2026 ومستهدفات 2027–2031، مع إمكانية إنشاء خطط وفترات أخرى دون تعديل برمجي.

## 2. القرارات المعتمدة في مرحلة المناقشة

| # | الموضوع | القرار |
|---|---|---|
| 1 | مستويات الهيكل | الجامعة ← الكلية أو المعهد ← القسم العلمي، إضافة إلى المراكز والإدارات المركزية. لكل مؤشر مستوى جمع محدد: قسم أو كلية أو جامعة. |
| 2 | الاستضافة | خادم داخل الجامعة، مع تصميم يسمح بالنقل لاحقًا. اختيار تنفيذي وليس إلزامًا تنظيميًا. |
| 3 | مصدر البيانات | البدء بالإدخال اليدوي واستيراد Excel بعد توحيد التعريفات. الربط بأنظمة الطلاب والموارد البشرية والمالية والبحث العلمي لاحقًا بعد التحقق من واجهاتها وصلاحياتها. |
| 4 | المرجع عند التعارض | **مستهدفات الجامعة من ملف Tier 1**، و**مستهدفات الكليات من ملف «مؤشرات الكليات»** وتُعامل توزيعًا لتحقيق مستهدفات الجامعة. كل تعارض يُعرض على **اللجنة العليا لـ Tier 1** ويُحفظ قرارها. **النظام لا يعدّل الأرقام تلقائيًا.** |
| 5 | الهيكل التنظيمي للكليات | يظهر في البرنامج رسمًا تنظيميًا بأسماء أعضائه وبياناتهم (القسم 4-17). وحدات الإعلام والتسويق، والتوظيف والتدريب، والابتكار وريادة الأعمال **تتبع عميد الكلية**. |
| 6 | الأولوية | اعتماد قاموس المؤشرات، ثم تسوية التعارضات، ثم فتح دورات محددة زمنيًا (عدة مرات) لجمع البيانات واعتمادها وإصدار تقرير الجامعة، مع مقارنة التقدم في الأداء بين الدورات. |
| 7 | نطاق التجربة | **التجربة على الجامعة كلها مرة واحدة** (كل الكليات والمعاهد والإدارات المركزية)، لا على كليات مختارة. انظر القسم 8-1 لضوابط تقليل المخاطر. |
| 8 | جهة حسم التعارضات | **اللجنة العليا لـ Tier 1**: تعتمد قاموس المؤشرات والمستهدفات وتوزيعها، وتحسم التعارضات، وتعتمد إعادة فتح البيانات المقفلة عند الحاجة. |

## 3. الهيكل التنظيمي والمستخدمون

### 3-1 إدارة الجهات

- تعريف الكليات والمعاهد والأقسام والمراكز والإدارات وعلاقاتها.
- تسجيل إنشاء جهة أو دمجها أو تغيير اسمها بتاريخ سريان.
- ربط البيانات التاريخية بالهيكل الذي سُجلت فيه.
- تحديد الجهة المسؤولة عن كل مؤشر والجهات المشاركة في توفير بياناته.
- تعطيل الجهة بدل حذفها حفاظًا على السجلات السابقة.

### 3-2 الأدوار والصلاحيات

| الدور | الصلاحيات الأساسية |
|---|---|
| رئيس الجامعة | الاطلاع الشامل، متابعة الأداء، إصدار التوجيهات |
| نائب رئيس الجامعة | متابعة نطاق اختصاصه والجهات التابعة له |
| اللجنة العليا لـ Tier 1 | اعتماد قاموس المؤشرات والمستهدفات وتوزيعها، وحسم التعارضات، واعتماد طلبات إعادة فتح القيم المقفلة. قراراتها تُسجَّل بأعضائها الحاضرين ورقم المحضر |
| مدير متابعة الخطة | إدارة دورات المتابعة والمستهدفات والتقارير والتعارضات |
| الجودة المركزية | مراجعة البيانات والأدلة والاعتماد النهائي وفق التفويض |
| عميد الكلية | متابعة الكلية واعتماد بياناتها |
| لجنة Tier 1 بالكلية | مراجعة بيانات الأقسام والتجميع والمتابعة |
| ممثل Tier 1 بالقسم | مراجعة بيانات القسم وإعادتها للتصحيح أو تمريرها |
| مدخل البيانات | إدخال البيانات ورفع الأدلة وإرسالها للمراجعة |
| مسؤول المبادرة | تحديث الأنشطة والإنجاز والتكاليف والمخاطر |
| المراجع / مستخدم الاطلاع | مشاهدة النطاق المسموح دون تعديل |
| مدير النظام التقني | إدارة الإعدادات والحسابات؛ **لا يحصل تلقائيًا على صلاحية اعتماد البيانات** |

- الصلاحية مرتبطة بالإجراء والجهة والمؤشر والفترة.
- يجوز للمستخدم حمل أكثر من دور، مع منع اعتماده النهائي لبيانات أدخلها هو إذا اقتضت سياسة الفصل بين المهام ذلك.

## 4. المتطلبات الوظيفية

### 4-1 الخطط والركائز والمعايير

- إنشاء خطة استراتيجية باسمها ومدتها وإصداراتها.
- تعريف الركائز والمعايير وترتيبها وأوزانها عند اعتماد منهجية أوزان.
- تحميل المعايير الاثني عشر ومؤشراتها بعد مراجعتها.
- استخدام المؤشر نفسه في أكثر من خطة.
- حفظ تاريخ اعتماد الخطة وكل تعديل لاحق.

### 4-2 قاموس المؤشرات

| المجموعة | البيانات |
|---|---|
| الهوية | كود ثابت، الاسم بالعربية والإنجليزية، الركيزة والمعيار |
| التعريف | الوصف، الغرض، نطاق التطبيق، الاستبعادات |
| القياس | نوع القيمة، الوحدة، المعادلة، البسط والمقام عند انطباقهما |
| الاتجاه | الأعلى أفضل، الأقل أفضل، أو نطاق مطلوب |
| الدورية | شهري، ربع سنوي، نصف سنوي، سنوي، أو مخصصة |
| الزمن | سنة ميلادية أو أكاديمية أو مالية، وفترة القياس |
| المسؤولية | مالك المؤشر، منتج البيانات، المراجع، جهة الاعتماد |
| المصدر | النظام أو التقرير أو السجل المرجعي |
| الإثبات | الأدلة المطلوبة وشروط قبولها |
| التجميع | طريقة احتساب قيمة الكلية والجامعة ومنع التكرار |
| الحوكمة | حالة الاعتماد، الإصدار، تاريخ السريان، سبب التعديل |
| الارتباطات | مؤشرات التصنيفات والاعتماد والمبادرات ذات الصلة |

**قواعد إلزامية:**

1. لا يُنشر مؤشر دون تعريف ووحدة ومصدر ومسؤول وقاعدة احتساب واضحة.
2. تُمنع المعادلات أو علاقات الاعتماد الدائرية بين المؤشرات.
3. تعديل المعادلة أو الوحدة بعد استخدامها ينشئ إصدارًا جديدًا.
4. لا تُعاد كتابة النتائج التاريخية بمعادلة جديدة دون إجراء معتمد.
5. يُميَّز بين: **صفر، غير متاح، غير منطبق، لم يُقدَّم**.
6. كل الاحتساب يتم في الخادم.

### 4-3 المستهدفات وخط الأساس

- تسجيل خط الأساس ومصدره وحالة اعتماده.
- مستهدف سنوي للجامعة ولكل جهة ينطبق عليها المؤشر.
- دعم المستهدفات العددية والنسبية والمالية والنطاقات والمراحل المنجزة.
- تسجيل البسط والمقام المستهدفين عندما يحتاج توزيع النسبة إليهما.
- مقارنة مجموع توزيع مستهدفات الكليات بمستهدف الجامعة، وإظهار الفجوة والجهات التي لم تستكمل توزيعها.
- توثيق كل تعديل للمستهدف بسبب وموافقة وتاريخ سريان، وحفظ النسخة السابقة.
- **مستهدفات الجامعة واحدة لكل مؤشر وسنة، ولكل كلية مستهدفاتها الخاصة:**
  - تقترحها الكلية (العميد أو لجنة الكلية) أو مدير متابعة الخطة، وتعتمدها اللجنة العليا لـ Tier 1 بحسب طبيعة الكلية وقدرتها على المساهمة في مستهدفات الجامعة.
  - الكلية بلا مستهدف خاص يسري عليها الموحد لكل كلية، ثم مستهدف الجامعة في النسب والمتوسطات.
- **ما تراه الكلية:**
  - مستهدفاتها **وحدها** بجانب مستهدفات الجامعة، في صفحة المستهدفات وتوزيعها والنتائج، ولا ترى مستهدفات الكليات الأخرى. تعرض أداة التوزيع لها إجمالي التوزيع على الجامعة دون أرقام كل كلية.
  - في النسب والمتوسطات: مستهدف الجامعة بجانب مستهدفها ونسبة إنجازها منه.
  - في الأعداد: حصة مستهدفها وحصة ما حققته من مستهدف الجامعة الكلي.
  - التوزيع الكامل على الكليات لمن نطاقه الجامعة: مدير متابعة الخطة، واللجنة العليا، ومن في حكمهما.
- **يقاس الأداء بالمستهدف المعتمد وحده** ([ADR-0003](adr/0003-approved-targets-only.md)):
  - المستهدف المقترح (من العميد أو لجنة الكلية أو مدير متابعة الخطة) لا يغير مقياس أي جهة قبل اعتماد اللجنة العليا له.
  - حتى يعتمد يسري آخر مستهدف معتمد: مستهدف الجهة لسنة سابقة، أو الموحد لكل كلية، أو مستهدف الجامعة لما لا يتغير بحجم الجهة.
  - يظهر المقترح في الإدخال والنتائج «بانتظار الاعتماد» دون أن يدخل أي حساب.
  - يشمل ذلك النماذج والنتائج وبطاقة الأداء والتقدم ومراجعة قيم الجامعة.
  - أدوات التخطيط والتوزيع تبقى تعرض المقترح، لأنها مادة قرار اللجنة.

**التجميع:** لا تُجمع النسب كلها بطريقة واحدة. الأصل نسبة مجموع البسط إلى مجموع المقام، مع طرق محددة لمؤشرات المتوسط المرجح، أو العد المميز بعد إزالة التكرار (مثل عدد الدول الممثلة والأبحاث المشتركة)، أو القياس المركزي.

### 4-4 التعارضات وجودة البيانات

لكل مشكلة سجل يتضمن: المؤشر والجهة والفترة، والقيم المتعارضة ومصدر كل منها، ونوع المشكلة ودرجة تأثيرها، والمسؤول والموعد، والقرار والمستند الداعم ومعتمِده.

**مسار الحسم:** مدير متابعة الخطة يجهز الحالة والبدائل ← تُعرض على **اللجنة العليا لـ Tier 1** في جلسة ← يُسجَّل القرار برقم المحضر وتاريخه ← يطبّق مدير متابعة الخطة القرار على القاموس أو المستهدفات كإصدار جديد. يمكن عرض عدة حالات في جلسة واحدة، ويُصدر النظام جدول أعمال الجلسة تلقائيًا من الحالات المفتوحة.

**الفحوص الآلية:**

- وحدة لا تناسب طبيعة المستهدف.
- نسبة تتجاوز الحدود المسموح بها في تعريف المؤشر.
- بسط أكبر من المقام حيث يمنعه التعريف.
- مقام صفري أو بيانات ناقصة.
- إجمالي لا يساوي مجموع فئاته (مثال: 24 جهة يجب أن يفسرها توزيع حالات الاعتماد كاملًا).
- سجلات مكررة بين الكليات.
- قفزة غير معتادة مقارنة بالفترة السابقة.
- غياب دليل إلزامي.

**الوضع الحالي:** سجل التعارضات المبدئي يضم **49 حالة** (12 عالية، 28 متوسطة، 9 منخفضة) استُخرجت من الملفين، وأهمها:

- مستهدفات «لكل كلية» تتجاوز مستهدف الجامعة كلها عند جمعها، مثل المعامل ودخل البحث وبراءات الاختراع.
- تعارضات داخل ملف Tier 1 نفسه، بين الجداول والرسوم البيانية، وبين صفحة الوضع الراهن وصفحة المبادرات.
- أعمدة سنوات ناقصة في جداول المعايير 5 و8 و9 و10 و11.
- نصوص تالفة في خطة مبادرات المعيار الأول، مثل «2039: 25%» و«9031 :2031».
- مؤشرات بلا تعريف أو معادلة، ومعظمها في المعيارين 8 و9.

### 4-5 دورات جمع البيانات

- إنشاء دورة قياس بفتراتها ومواعيد فتحها وإغلاقها، وتكرارها أكثر من مرة في السنة.
- توليد نماذج كل جهة تلقائيًا من المؤشرات المنطبقة عليها.
- تعيين المكلفين والمراجعين والمواعيد النهائية.
- حفظ المسودات واستكمالها لاحقًا.
- عرض آخر قيمة معتمدة والمستهدف أثناء الإدخال.
- طلب تفسير للانحرافات الكبيرة.
- منع إرسال نموذج ينقصه متطلب إلزامي.
- حالة كل جهة: لم تبدأ، قيد الإعداد، قيد المراجعة، معادة للتصحيح، معتمدة، متأخرة.

### 4-5-1 سهولة إدخال البيانات ووضوح النماذج والتحقق من صحتها ⟵ إضافة

نماذج إدخال واضحة لكل كلية وقسم وإدارة ومركز. تعرض المطلوب من الجهة حسب اختصاصها والفترة، وتساعد المستخدم على الإدخال الصحيح بأقل جهد:

1. **المطلوب من كل جهة:** المستخدم يرى المؤشرات والنماذج المكلف بها فقط، ومع كل منها المسؤول، والموعد النهائي، والحالة، والبيانات والأدلة الناقصة.
2. **نماذج منظمة:**
   - مجموعات وخطوات قصيرة بعناوين مفهومة.
   - تمييز الحقول الإلزامية من الاختيارية.
   - لا تظهر إلا الحقول المتعلقة باختيارات المستخدم.
3. **توضيح كل حقل:**
   - اسم واضح، ووحدة القياس، والفترة المطلوبة، وتعليمات مختصرة، ومثال عند الحاجة.
   - تعريف المؤشر ومصدر بياناته وطريقة احتسابه متاحة دون مغادرة النموذج.
4. **تقليل الكتابة والتكرار:**
   - قوائم وبحث واختيارات وتواريخ بدل النص الحر قدر الإمكان.
   - تعبئة بيانات الجهة والمستخدم والفترة تلقائيًا.
   - جلب البيانات المتاحة من مصادرها المعتمدة بدل إعادة إدخالها.
5. **التحقق الفوري** أثناء الإدخال وعند الحفظ والإرسال، بقواعد قابلة للضبط لكل مؤشر:

| نوع التحقق | مثال |
|---|---|
| نوع القيمة | عدد صحيح لعدد الطلاب، وقيمة عشرية عند السماح بها |
| الحدود المسموح بها | منع القيم السالبة للأعداد التي لا تقبلها |
| النطاق | نسبة من 0 إلى 100 فقط حين يكون ذلك نطاق المؤشر |
| العلاقة بين الحقول | عدد المستفيدين لا يتجاوز إجمالي الفئة المستهدفة |
| التواريخ | تاريخ النهاية لا يسبق تاريخ البداية |
| اكتمال البيانات | اشتراط المقام والدليل إذا تطلبهما تعريف المؤشر |
| اتساق الإجماليات | مجموع الفئات يساوي الإجمالي وفق قاعدة المؤشر |
| التكرار | منع تكرار بيانات المؤشر نفسه للجهة والفترة والإصدار |
| التغير التاريخي | تنبيه عند اختلاف كبير عن آخر قيمة معتمدة |

6. **الحساب التلقائي:**
   - يدخل المستخدم البيانات الأساسية (البسط والمقام)، ويحسب النظام النسبة والإجماليات والقيم المشتقة.
   - تظهر المعادلة بوضوح.
   - تُمنع التعديلات اليدوية على النتائج المحسوبة.
7. **رسائل تصحيح مفهومة** بجوار الحقل، توضح المشكلة وطريقة تصحيحها، مثل: «عدد المستفيدين 520 يتجاوز إجمالي الطلاب 500؛ راجع إحدى القيمتين». ويحتفظ النموذج بباقي المدخلات عند وجود خطأ.
8. **الخطأ غير التحذير:**
   - الخطأ المؤكد يمنع الإرسال.
   - التحذير يسمح بالإرسال مع تفسير، أو بالإحالة للمراجعة حسب السياسة.
   - لا يُرفض رقم لمجرد اختلافه الكبير عن العام السابق.
9. **حالات البيانات:**
   - خيارات مستقلة لـ«صفر» و«غير متاح» و«غير منطبق»، مع طلب السبب عند الحاجة.
   - الحقل الفارغ لا يتحول إلى صفر تلقائيًا.
10. **الحفظ والاستكمال:**
    - حفظ كمسودة، وحفظ تلقائي مع إظهار آخر وقت حفظ.
    - تنبيه قبل مغادرة نموذج فيه تغييرات غير محفوظة.
    - إظهار نسبة اكتمال النموذج والحقول المتبقية.
11. **مراجعة قبل الإرسال:**
    - ملخص للقيم والأدلة والتنبيهات قبل التأكيد.
    - بيان الجهة التي سينتقل إليها النموذج للمراجعة.
    - عند الإعادة للتصحيح تُبرز الحقول المطلوبة وملاحظات المراجع.
12. **حماية البيانات أثناء العمل:**
    - لا كتابة فوق تعديل أحدث أجراه مستخدم آخر دون تنبيه.
    - قواعد التحقق نفسها تعمل في الخادم لكل طرق الإدخال، بما فيها Excel والتكاملات.

**معيار القبول:**
- يعرف المستخدم المطلوب من جهته، ويستكمل النموذج اعتمادًا على التعليمات الموجودة داخله.
- يمنع النظام إرسال القيم المخالفة للقواعد الإلزامية، ويشرح أسباب الرفض وطريقة التصحيح.
- تُحفظ المسودات دون فقد أي بيانات.

### 4-6 المراجعة والاعتماد

المسار الافتراضي لبيانات الأقسام:

**مدخل البيانات ← ممثل Tier 1 بالقسم ← لجنة Tier 1 بالكلية ← العميد ← الجودة المركزية**

- مسارات مختلفة للمؤشرات المركزية.
- اعتماد جزئي للمؤشرات إذا سمحت السياسة.
- الإعادة للتصحيح مع سبب واضح.
- تعليقات وردود مرتبطة بكل قيمة.
- تفويض مؤقت بتاريخ بداية ونهاية.
- منع تجاوز أي مرحلة دون صلاحية وإجراء مسجل. التجاوز المسموح (الاعتماد المباشر، [ADR-0002](adr/0002-direct-approval-paths.md)):
  - **العميد** يحيل نموذج القسم أو الكلية من خطوة ممثل القسم أو لجنة الكلية إلى الجودة المركزية، بإجراء «اعتماد مباشر من العميد».
  - **لجنة الكلية** تحيل نموذج القسم من خطوة ممثل القسم إلى العميد، بإجراء «اعتماد مباشر لنموذج القسم».
  - التجاوز **اختيار صريح** بجانب الاعتماد العادي، لا يحدث تلقائيًا، ويلزمه **سبب مكتوب** يسجل في سجل النموذج، وتعلَّم الخطوات المتخطاة فيه.
  - من يملك تمرير النموذج في خطوته (عاديًا أو مباشرًا) يملك **إعادته للتصحيح**.
  - إشعار «ينتظر مراجعتك» لمراجعي الخطوة العاديين، ويظهر النموذج لأصحاب الاعتماد المباشر في قائمة «بانتظاري».
  - الاعتماد المباشر في نطاق الدور المانح وحده ([ADR-0001](adr/0001-scoped-special-actions.md)).
- قفل القيم المعتمدة، وإعادة فتحها بطلب مسبب وموافقة محددة ([ADR-0004](adr/0004-reopen-by-committee-decision.md)):
  - يطلب إعادة الفتح من يملك «طلب إعادة الفتح» (مدير متابعة الخطة)، بسبب.
  - تقرره **اللجنة العليا** باعتماد برقم المحضر أو رفض بسبب، ولا يقرر الطلب مقدمه. وطلب واحد معلق لكل نموذج.
  - النموذج يبقى معتمدًا ومقفلًا حتى القرار.
  - عند الاعتماد تحفظ لقطة من القيم المعتمدة، وتبقى هي الرسمية في النتائج وبطاقة الأداء والتقدم حتى يعاد اعتماد النموذج.
  - إعادة فتح نموذج في دورة مغلقة خارج هذا القرار.
- الاحتفاظ بالقيمة السابقة وكل مراحل اعتمادها.

### 4-7 الأدلة والمستندات

- رفع PDF وExcel والصور وغيرها وفق سياسة ملفات محددة، مع فحص النوع والحجم.
- ربط الدليل بالمؤشر والجهة والفترة والقيمة.
- تسجيل مصدر المستند وتاريخه وإصداره.
- معاينة الملفات المدعومة وتنزيلها حسب الصلاحية.
- منع الحذف النهائي لدليل مرتبط ببيانات معتمدة؛ يُسمح بإبطاله أو استبداله بإصدار أحدث مع حفظ التاريخ.
- تطبيق مدد احتفاظ تعتمدها الجامعة.

### 4-8 استيراد Excel

- قوالب حسب الجهة والفترة والمؤشرات، بأكواد ثابتة للمؤشرات والجهات.
- رفع الملف إلى منطقة مراجعة قبل إدخال بياناته.
- عرض أخطاء الصفوف وتصديرها في ملف تصحيح.
- كشف التكرار والتعارض مع القيم الموجودة.
- عرض التغييرات قبل تأكيد الاستيراد.
- تسجيل من استورد ومتى ونتيجة العملية.
- مرور البيانات المستوردة بمسار الاعتماد نفسه.
- عملية مستقلة لاستيراد البيانات التاريخية مع بيان مصدرها.

### 4-9 المبادرات والمشروعات والميزانيات

**بطاقة المبادرة:** الكود والاسم والوصف والأهداف؛ المعيار والمؤشرات المستفيدة؛ الجهة المالكة والجهات المشاركة ومدير التنفيذ؛ الأنشطة والمخرجات ومراحل التسليم؛ التواريخ المخططة والفعلية؛ التكلفة التقديرية والميزانية المعتمدة والإنفاق الفعلي؛ مصدر التمويل والعملة؛ المخاطر والمعوقات والتبعيات؛ الأدلة ومحاضر الاستلام.

- حساب الإنجاز وفق أوزان معتمدة للأنشطة.
- تفسير التأخر وتجاوز الميزانية.
- طلبات تعديل النطاق أو المدة أو التكلفة.
- مقارنة الإنجاز التنفيذي والمالي بتطور المؤشرات.
- **يُعرض الارتباط بين المبادرة والمؤشر دون اعتبار تحسن المؤشر دليلًا على أن المبادرة وحدها سببته.**

ملف Tier 1 يتضمن 9 مبادرات تقريبًا لكل معيار، لكل منها هدف وأنشطة وجهة مسؤولة وتكلفة تقديرية وإطار زمني ومؤشر أداء. تُستخرج في المرحلة الثانية.

### 4-10 لوحات المتابعة

**لوحة رئيس الجامعة:** المعايير الاثنا عشر وحالة كل منها؛ الإنجاز مقابل المستهدف السنوي والفجوة حتى 2031؛ اكتمال البيانات ونسبة اعتمادها؛ الجهات المتأخرة؛ المبادرات المتعثرة والانحرافات المالية؛ القرارات المطلوبة والموضوعات المصعّدة.

**لوحة المعيار:** خط الأساس والقيم الحالية والمستهدفات؛ تطور كل مؤشر؛ مساهمة الجهات والمبادرات؛ الأدلة والتفسيرات.

**لوحة الكلية والقسم:** مؤشرات الجهة ومهامها ومواعيدها؛ البيانات المعادة للتصحيح؛ المقارنة بالفترات السابقة؛ الإجراءات التصحيحية.

**عام:** خريطة حرارية (الجهات × المعايير)، وفلاتر، والانتقال من الإجمالي إلى التفاصيل حسب الصلاحية. ألوان الأداء وفق حدود معلنة. أي درجة إجمالية للمعيار تحتاج منهجية معتمدة للتطبيع والأوزان والبيانات الناقصة.

### 4-10-1 عرض البيانات ولوحات المؤشرات والتقارير ⟵ إضافة

يعتمد النظام على العرض البصري ببطاقات مؤشرات ورسوم واضحة، حتى تعرف قيادات الجامعة والكليات الوضع الحالي وتقارنه بالمستهدف وتحدد الفجوات والجهات المتأخرة بسرعة.

1. **بطاقة المؤشر:** القيمة الحالية، والمستهدف، والفجوة، والتغير عن الفترة السابقة، وحالة الأداء، وتاريخ آخر تحديث.
2. **الرسم المناسب لطبيعة البيانات:**

| البيانات أو المقارنة | أسلوب العرض |
|---|---|
| القيمة الحالية مقابل المستهدف | أعمدة مقارنة، أو شريط تقدم بعلامة للمستهدف |
| تطور المؤشر عبر السنوات | رسم خطي للقيم الفعلية والمستهدفات |
| مقارنة الكليات والأقسام | أعمدة أفقية مرتبة |
| توزيع الكليات حسب حالة الاعتماد | أعمدة مكدسة، أو رسم حلقي عند قلة الفئات |
| أداء الكليات مقابل المعايير | خريطة حرارية |
| المبادرات ومواعيد تنفيذها | مخطط زمني Gantt |
| الميزانية المخططة والفعلية | أعمدة مقارنة توضح الانحراف |
| مراحل إدخال البيانات واعتمادها | أعمدة بأعداد النماذج في كل حالة |
| البيانات التفصيلية | جداول قابلة للبحث والفرز والتصفية |

3. **حالة الأداء:** أخضر وأصفر وأحمر وفق حدود معتمدة لكل مؤشر، مع وصف نصي أو رمز بجوار اللون. نقص البيانات أو عدم اعتمادها حالة مستقلة، **ولا يُحسب ضعفًا في الأداء** ([ADR-0005](adr/0005-missing-data.md)):
   - **«غير متاح»** نقص في البيانات: لا رقم ولا صفر.
   - **«غير منطبق»** يخرج الجهة من الجهات المطلوب منها رقم.
   - أي قيمة مجمعة (مجموع أو نسبة أو متوسط) من بعض الجهات المطلوبة فقط تظهر «بيانات جزئية» بقيمتها وعدد ما اعتمد منها، ولا يحكم عليها حتى تكتمل.
   - الدرجة المركبة والفئة في بطاقة الأداء تتبعان ملف الإطار الرسمي: المؤشر بلا قيمة صفر. والشاشة تقوله صراحة وتعرض كم مؤشرًا له قيمة ([kpi-framework.md](kpi-framework.md)).
4. **التفاعل:**
   - التصفية حسب السنة والفترة والكلية والقسم والمعيار.
   - التفاصيل عند المرور على العنصر أو الضغط عليه.
   - الانتقال من المؤشر الإجمالي إلى بيانات الجهات المكوِّنة له، حسب الصلاحيات.
5. **وضوح العرض:**
   - يظهر عنوان الرسم، ووحدة القياس، والفترة، ومصدر البيانات، وحالة اعتمادها.
   - التمييز واضح بين الفعلي والمستهدف والمتوقع.
   - يُراعى هل الارتفاع هو الأفضل أم الانخفاض.
6. **ملخص مقروء بجانب الرسم** يوضح أهم نتيجة، مثل: «حققت الكلية 80% من المستهدف السنوي، مع تحسن قدره 5 نقاط مئوية عن العام السابق».
7. **التقارير المرئية:** ملخص تنفيذي بصري، وأهم المؤشرات والاتجاهات والفجوات والإجراءات المطلوبة، مع الجداول التفصيلية للمراجعة.
8. **التصدير والطباعة:** تبقى الرسومات والعناوين والأرقام واضحة عند التصدير إلى PDF وPowerPoint وExcel، مع دعم العربية واتجاه اليمين إلى اليسار وهوية جامعة العاصمة.
9. **سهولة الاستخدام:**
   - لا ازدحام في الشاشة، ولا رسومات ثلاثية الأبعاد، ولا زخارف تعوق قراءة الأرقام.
   - عرض جدولي بديل لكل رسم.
   - اللوحات تلائم الحاسب والهاتف والشاشات الكبيرة.

**معيار القبول:** يحدد المستخدم من العرض مباشرة القيمة الحالية، والمستهدف، والفجوة، واتجاه الأداء، وحالة اعتماد البيانات. وتتطابق كل أرقام الرسومات مع الجداول والتقارير لنفس الفلاتر والفترة.

### 4-10-2 سهولة الاستخدام ⟵ إضافة

- **«مطلوب منك»** أول ما يراه المستخدم: مهامه المعلقة في نطاقه، وكل مهمة تفتح مكان تنفيذها مباشرة.
- **صفحة واحدة لكل مؤشر:** التعريف والمستهدفات وتوزيعها على الكليات والتعارضات المرتبطة، دون التنقل بين شاشات.
- **بحث موحد** بكود المؤشر أو اسمه أو اسم الكلية من أعلى كل صفحة.
- **الوصول إلى أي إجراء بنقرتين على الأكثر** من الصفحة الرئيسية.
- **حقول بتسميات واضحة** وشرح مختصر بجوار كل حقل، ورسائل خطأ تقول ما المطلوب لا ما الخطأ التقني.
- **الأزرار تظهر بحسب الصلاحية فقط**؛ لا يرى المستخدم إجراءً لا يملكه.
- **يعمل دون تدريب:** الحالة الحالية والخطوة التالية مكتوبتان في كل صفحة.

### 4-11 المقارنة والتوقعات

- مقارنة التقدم بين دورات القياس المتتالية.
- مقارنة الجهات المتشابهة على المؤشرات المنطبقة فقط، مع إظهار التغطية وجودة البيانات بجانب الترتيب.
- إمكانية تعطيل الترتيب لمؤشرات لا تصلح للمقارنة.
- عرض الاتجاه التاريخي والتوقع بافتراضاته، ولا يُنشأ توقع عند عدم كفاية البيانات.
- فصل بصري واضح بين الفعلي والمستهدف والمتوقع.

### 4-12 التصنيفات الدولية

- تسجيل نتيجة كل تصنيف وإصداره وسنة نشره، ودعم المركز الدقيق والنطاق وغياب الترتيب.
- حفظ الدرجات الفرعية ومصدرها ونسخة المنهجية.
- ربط المؤشرات الداخلية بمكونات التصنيف المناسبة.
- إدارة مهام إعداد البيانات وتقديمها ومراجعتها.
- **محاكي السيناريوهات (مرحلة متقدمة):** تغيير مدخلات محددة ومقارنتها بخط الأساس، وبيان الأثر على الدرجة حين تسمح المنهجية، مع إظهار القيود. **لا يقدم مركزًا مستقبليًا مؤكدًا**، لأن المركز يعتمد على أداء الجامعات الأخرى أيضًا.

التصنيفات الواردة في ملف Tier 1 (2026): QS، وTHE Impact، وTHE Interdisciplinary، وCWTS Leiden، وRUR، وU.S. News، وCWUR، وARU، وQS Sustainability، وWebometrics، وUniRank، وQS Arab Region، وQS Arts & Design.

### 4-13 الاعتماد وضمان الجودة

- اعتماد المؤسسات والكليات والبرامج والمعامل: الجهة والنوع والحالة والنطاق.
- تاريخ المنح والانتهاء والوثائق، وتنبيهات قبل الانتهاء بمدد قابلة للضبط.
- متابعة الزيارات والملاحظات وخطط التحسين.
- لكل إجراء تصحيحي مسؤول وموعد ودليل إغلاق.

### 4-14 التقارير والتصدير

- تقرير شهري للكلية، وتقرير مجمع للجامعة، وتقارير ربع سنوية وسنوية.
- تقارير الفجوات وجودة البيانات والتأخر والاعتمادات والمبادرات والميزانيات والمخاطر.
- تصدير PDF وExcel وPowerPoint بقوالب وهوية الجامعة، بالعربية ومن اليمين لليسار.
- يظهر في كل تقرير الفترة وتاريخ الاستخراج وحالة اعتماد البيانات.
- حفظ نسخة ثابتة من كل تقرير رسمي صادر.
- تطبيق صلاحيات المستخدم على محتوى التقرير والتصدير.

### 4-14-1 منشئ التقارير والتحكم في المخرجات ⟵ إضافة (المرحلة الثانية)

منشئ تقارير يمكّن المستخدم المخوّل من تحديد محتوى المخرجات وشكلها وترتيبها وصيغها، دون تعديل برمجي:

1. **اختيار المحتوى:** المؤشرات والبيانات والجداول والرسومات والأقسام، مع إظهار أو إخفاء كل عنصر: التفاصيل، والتعليقات، والتوصيات، والأدلة، ومصادر البيانات.
2. **ترتيب العناصر:**
   - تغيير ترتيب الأقسام والبطاقات والرسومات والجداول بالسحب والإفلات.
   - التحكم في ترتيب الأعمدة والصفوف، وتحديد فواصل الصفحات.
3. **نطاق التقرير:** الكليات، والأقسام، والإدارات، والمراكز، والمعايير، والمؤشرات، والفترات، مع المقارنة بين جهات أو سنوات.
4. **تخصيص الجداول:**
   - الأعمدة: اختيارها وتسمياتها وعرضها وترتيبها.
   - الفرز والتجميع والتصفية.
   - الإجماليات والمجاميع الفرعية حسب قواعد احتساب المؤشرات المعتمدة.
5. **تخصيص الرسومات:** نوع الرسم، والمؤشرات المعروضة وترتيبها، والعناوين، وتسميات البيانات، والوحدات، مع إظهار المستهدف وخط الأساس والمقارنات.
6. **تخصيص التصميم:**
   - الصفحة: حجمها واتجاهها وهوامشها.
   - الهوية: الخطوط والألوان والشعار والغلاف.
   - الترويسة والتذييل وترقيم الصفحات، وبيانات إعداد التقرير واعتماده.
   - العربية والإنجليزية واتجاه الكتابة المناسب لكل منهما.
7. **قوالب محفوظة:**
   - قوالب شخصية أو مشتركة حسب الصلاحيات، تُنسخ وتُعدَّل.
   - قالب افتراضي لكل نوع تقرير.
   - إصدارات للقوالب الرسمية.
8. **معاينة قبل الإصدار:** تُظهر شكل المخرجات وفواصل الصفحات والبيانات والفلاتر المستخدمة، مع إمكانية التعديل قبل الطباعة أو التنزيل.
9. **صيغ التصدير:**

| نوع المخرج | الصيغ |
|---|---|
| التقارير والمستندات | PDF وWord (DOCX) وHTML |
| البيانات والجداول | Excel (XLSX) وCSV |
| العروض التقديمية | PowerPoint (PPTX) |
| الرسومات واللوحات | PNG وSVG وPDF |
| الطباعة | نسخة مهيأة للطباعة بمقاسات الصفحات المعتمدة |

   - الجداول والنصوص والرسومات قابلة للتحرير في الصيغ التي تدعم ذلك، ويُوضَّح أي عنصر يُصدَّر كصورة.
   - تُختبر جودة كل صيغة على حدة.
10. **خيارات التصدير:**
    - العرض الحالي، أو كل النتائج المطابقة للفلاتر.
    - تقرير واحد، أو تقرير منفصل لكل جهة.
    - تجميع الملفات في ZIP، وتحديد أسماء الملفات.
11. **التقارير الدورية:** جدولة التوليد بقوالب وفلاتر محفوظة، مع تحديد الفترة والجهات المستفيدة وطريقة الإتاحة أو الإرسال حسب الصلاحيات.
12. **سلامة البيانات والصلاحيات:**
    - التخصيص يقتصر على البيانات المسموح للمستخدم بالوصول إليها.
    - لا يغيّر القيم المعتمدة ولا معادلاتها.
    - التقرير الرسمي يحمل حدًا أدنى إلزاميًا من السياق: الفترة، وحالة اعتماد البيانات، وتاريخ الإصدار، حتى لا يخرج تقرير مضلل أو ناقص السياق.
13. **توثيق المخرجات:** يُسجَّل من أصدر التقرير ومتى، وصيغته، والفلاتر، والقالب المستخدم. وتُحفظ نسخة ثابتة من التقارير الرسمية للرجوع إلى المحتوى نفسه لاحقًا.

**معيار القبول:**
- ينشئ المستخدم تقريرًا بالمحتوى والترتيب والتنسيق الذي يحدده، ويحفظه ويعيد استخدامه ويصدّره بالصيغ المعتمدة.
- تتطابق الأرقام والفلاتر والصلاحيات في جميع المخرجات.

### 4-15 الإشعارات والتكليفات

- إشعارات داخل النظام وبالبريد: التكليف، قرب الموعد، التأخر، الإعادة، الاعتماد.
- تصعيد التأخر وفق مدد ومستويات محددة.
- توجيه مرتبط بمؤشر أو مبادرة، له مسؤول وموعد، ومتابعة تنفيذه وتعليقاته وأدلة إغلاقه.
- تسجيل حالة إرسال الإشعارات وإعادة محاولة الفاشل منها.

### 4-16 الذكاء الاصطناعي والتكامل

**الذكاء الاصطناعي:** اقتراح حالات شذوذ للمراجعة؛ مسودة تحليل مرتبطة بالأرقام ومصادرها؛ إجابة بالعربية ضمن البيانات المصرح بها للمستخدم؛ مراجعة بشرية قبل أي إصدار رسمي. **يُمنع المساعد من تعديل القيم أو اعتمادها.**

**التكامل:** موصلات للطلاب والموارد البشرية والمالية والبحث العلمي؛ مصدر مرجعي محدد لكل حقل؛ مزامنة مجدولة مع سجل أخطاء وإعادة محاولة؛ منع التكرار عند إعادة الاستيراد؛ حفظ وقت الجلب ومصدره؛ لا تتجاوز البيانات المستوردة مسار المراجعة إلا بسياسة اعتماد صريحة.

### 4-17 الهيكل التنظيمي لـ Tier 1 بالكليات ⟵ إضافة

الهيكل المقترح في ملف الكليات (ص7)، وكل وحداته **تتبع عميد الكلية مباشرة**: **لجنة متابعة Tier 1**، و**المجلس الاستشاري الصناعي**، و**وحدة الإعلام والتسويق**، و**مركز التوظيف والتدريب ومتابعة الخريجين**، و**وحدة الابتكار وريادة الأعمال**، و**الأقسام العلمية**، ولكل قسم ممثل Tier 1 وشريك صناعي. مهام كل وحدة مسجلة في الملف المرجعي.

**المتطلبات:**

1. **قالب الهيكل:** تعريف الهيكل المرجعي مرة واحدة على مستوى الجامعة: الوحدات وتبعيتها واختصاصاتها والمناصب في كل وحدة. تُنشأ هياكل الكليات منه، ويجوز لكل كلية إضافة وحدات أو مناصب بموافقة.
2. **الرسم التنظيمي التفاعلي:** شجرة تُرسم تلقائيًا من البيانات. كل صندوق فيه اسم الوحدة، وتحته أعضاؤها بالاسم والمنصب والصورة الشخصية. الضغط على عضو يعرض بطاقته، والضغط على وحدة يعرض اختصاصاتها.
3. **بيانات العضو:** الاسم، الدرجة والصفة الوظيفية، المنصب في الهيكل، القسم أو الوحدة، جهة العمل للأعضاء من خارج الجامعة (مثل ممثل الشريك الصناعي)، البريد، الهاتف، الصورة، تاريخ بداية العضوية ونهايتها، رقم قرار التشكيل وتاريخه.
4. **الشريك الصناعي لكل قسم:** اسم الجهة ونشاطها ومنسقها وتاريخ الاتفاقية، ويُربط بمؤشرات الشراكات الصناعية (S05-03 وS04-09).
5. **المستندات:** رفع صورة الهيكل المعتمد رسميًا وقرارات التشكيل، مع حفظ الإصدارات السابقة.
6. **تاريخ التشكيلات:** عند تغيير عضو تُغلق عضويته بتاريخ ولا تُحذف، ويمكن عرض الهيكل كما كان في أي تاريخ.
7. **الربط بالصلاحيات:** العضوية في الهيكل تقترح الدور المناسب في النظام، مثل ممثل Tier 1 بالقسم الذي يقترح له دور مراجع القسم. **لا يُمنح الدور إلا بعد اعتماد مدير متابعة الخطة**، ويُسحب تلقائيًا عند انتهاء العضوية.
8. **مؤشر اكتمال الهيكل:** لوحة تبين الكليات التي لم تستكمل تشكيلها: قسم بلا ممثل Tier 1، أو قسم بلا شريك صناعي، أو مجلس استشاري بلا أعضاء من الصناعة، أو منصب شاغر.
9. **سجل اجتماعات** (المرحلة الثانية): المجلس الاستشاري الصناعي يجتمع شهريًا ولجنة Tier 1 ترفع تقريرًا شهريًا، فيُسجَّل لكل اجتماع تاريخه وحضوره ومحضره وقراراته وتكليفاته.
10. **الخصوصية:** الهاتف والبريد الشخصي يظهران حسب الصلاحية فقط.
11. **التصدير:** تصدير الرسم التنظيمي PDF وصورة بهوية الجامعة، وقائمة الأعضاء Excel.
12. **الاستيراد الأول:** قالب Excel لأعضاء الهيكل متاح في الملف المرجعي (ورقة «أعضاء الهيكل (قالب)»).

### 8-1 ضوابط التجربة على الجامعة كلها

تشغيل الجامعة كلها مرة واحدة يعني نحو 24 كلية ومعهدًا وأقسامها والإدارات المركزية في الدورة نفسها. أي خلل في نموذج أو تعريف سيظهر في كل الجهات معًا، لذلك تلزم الضوابط الآتية:

1. **بروفة داخلية قبل الفتح:** يُدخل فريق متابعة الخطة بيانات جهة واحدة كاملة بنفسه، ويمر بالمسار كله حتى إصدار التقرير. الهدف اكتشاف أخطاء النماذج قبل أن تراها الجهات.
2. **دورة تجريبية بمؤشرات معتمدة فقط:** لا يدخل الدورة الأولى إلا المؤشرات التي اعتمدت اللجنة العليا تعريفها. المؤشرات ذات التعارضات المفتوحة تُؤجل إلى دورة لاحقة بدل إيقاف الدورة كلها.
3. **فتح متدرج للحسابات:** تُفعَّل الحسابات وتُعقد التدريبات على دفعات خلال أيام قليلة قبل موعد الفتح، لكن الدورة نفسها تُفتح للجميع في التاريخ نفسه.
4. **دعم مخصص:** نقطة اتصال لكل كلية (ممثل لجنة Tier 1)، وقناة دعم مركزية، ودليل مختصر لمدخل البيانات.
5. **لوحة متابعة الدورة:** حالة كل جهة لحظيًا، مع تذكيرات وتصعيد آلي، حتى يرى فريق المتابعة المتأخرين مبكرًا.
6. **اختبار الحمل** يُجرى على عدد مستخدمين يقارب الحمل المتوقع في الأيام الأخيرة قبل الإغلاق، وهي ذروة الاستخدام.
7. **تمديد مضبوط:** يمكن تمديد موعد جهة بعينها بقرار مسجل دون إعادة فتح الدورة للجميع.
